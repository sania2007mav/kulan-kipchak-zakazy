# Техническое задание  
## Заказы покупателя и частичные отгрузки в 1С:Бухгалтерии КЗ  
**Клиент:** ТОО «Құлан Қыпшақ»  
**Платформа:** 1С:Бухгалтерия для Казахстана 3.0 (1С:Фреш), доработка расширением  
**Дата:** 27.10.2026  

---

### 1. Цель

Дать возможность работать с заказами покупателя прямо в бухгалтерской базе:  
один заказ → несколько реализаций ТМЗ и услуг, с понятным остатком «сколько ещё отгрузить» — без внедрения полного УНФ и без обмена Бух ↔ УНФ.

---

### 2. Что делаем (входит в объём)

Оценка трудозатрат — ориентир для КП (чел.-часы).

1. **Документ «Заказ покупателя»** — **4 ч**  
   Шапка: организация, контрагент, договор, склад, валюта, комментарий.  
   Табличная часть: номенклатура, количество, цена, % скидки, сумма.  
   Проведение документа. Печатная форма. Размещение в разделе «Продажа».

2. **Связка «заказ → реализации»** — **5 ч**  
   Из заказа — ввод на основании: реализация ТМЗ и услуг, счёт на оплату.  
   По одному заказу допускается **несколько** реализаций.  
   В реализации фиксируется связь с заказом.  
   Контроль: нельзя отгрузить больше, чем осталось по заказу (по количеству номенклатуры).

3. **Остаток к отгрузке** — **3 ч**  
   Учёт: заказано / отгружено / осталось.  
   В форме заказа видно количество «не отгружено» по строкам.  
   При создании следующей реализации подставляется **остаток**, а не полный заказ.

4. **Шкала отгрузки в списке заказов** — **2 ч**  
   Колонка «Отгружено, %» (0–100).  
   Цветовое оформление ячейки / полоска: мало / частично / полностью (как на согласованном макете).  
   По желанию — простой статус (в работе / частично / отгружен).

5. **Ответственный (менеджер)** — **2 ч**  
   Поле на заказе (справочник пользователей).  
   При вводе реализации — перенос с заказа.  
   Отбор в списке заказов.  
   Один простой отчёт / выборка «по менеджеру» (без переделки типовых бухгалтерских отчётов).

**Итого по п. 1–5: 16 ч** (включая тест и выкладку во Фреш).

6. **Обмен с бухгалтерской базой через COM-соединение** — **18 ч**  
   Заказы и реализации ведутся в управленческой базе (с доработкой по заказам). В официальную бухгалтерскую базу уходят **только реализации ТМЗ и услуг с отметкой «Отправлять в бухгалтерскую базу»**. Обмен односторонний: из управленческой базы в бухгалтерскую.

   **6.1. Когда отправляется реализация**  
   - Кнопка «Отправить в бухгалтерию» в форме документа реализации.  
   - Та же команда в списке реализаций, для одного или нескольких выделенных документов.  
   - Автоматически, регламентным заданием по расписанию (интервал задаётся в настройках): отправляются отмеченные реализации, которые ещё не отправлены или изменены после отправки.  

   Отметку «Отправлять в бухгалтерскую базу» можно поставить в заказе, тогда она переносится в реализацию при вводе на основании. Отправляются только проведённые реализации.

   **6.2. Статус и повторная отправка**  
   - В документе и колонкой в списке видно состояние: «Не отправлен», «Отправлен (№ и дата документа в БК)», «Ошибка (текст)».  
   - Связь «реализация в управленке ↔ документ в БК» хранится, поэтому повторная отправка обновляет тот же документ, а не создаёт дубль.  
   - Если бухгалтер уже провёл документ в БК, поведение задаётся настройкой: перезаписать и перепровести или не трогать (тогда в журнал пишется предупреждение).  
   - Журнал обмена: дата, документ, результат, текст ошибки.  
   - Если в управленке удалить реализацию или снять с неё отметку после отправки, документ в БК автоматически не удаляется — в журнал пишется предупреждение.

   **6.3. Сопоставление справочников**

   | Объект | Ищем в БК по | Если не найден |
   |---|---|---|
   | Организация | БИН | Ошибка, документ не отправляется |
   | Контрагент | БИН / ИИН | По настройке: **создать** (наименование, полное наименование, БИН/ИИН, юр./физ. лицо) **или оставить поле пустым**. Если БИН/ИИН не заполнен — не ищем, поле пустое, предупреждение в журнале |
   | Договор | У найденного контрагента и организации: номер + дата договора, затем наименование | По настройке: создать (вид «С покупателем», валюта, номер, дата), подставить основной договор контрагента или оставить пустым |
   | Номенклатура | Артикул | Нет артикула — не ищем. Не найден — по настройке: создать (наименование, артикул, вид, единица) или оставить строку с пустой номенклатурой |
   | Склад | Наименование | Склад по умолчанию из настроек |
   | Валюта | Код (398 — KZT) | Валюта регламентированного учёта |
   | Единица измерения | Код единицы | Базовая единица номенклатуры в БК |

   Ставка НДС и счета учёта не переносятся: их заполняет сама бухгалтерская база по настройкам номенклатуры и организации, как при ручном вводе.

   **6.4. Настройки обмена** (одна форма в разделе «Администрирование»)  
   - Подключение к бухгалтерской базе: путь к файловой базе или сервер и имя базы, пользователь, пароль, кнопка «Проверить подключение».  
   - Создавать контрагента, если он не найден по БИН/ИИН: да / нет.  
   - Создавать договор, если не найден: создать / основной договор / пусто.  
   - Создавать номенклатуру, если она не найдена по артикулу: да / нет.  
   - Склад по умолчанию.  
   - Проводить документ в БК после загрузки: да / нет (при «нет» реализация приходит записанной, бухгалтер проверяет и проводит сам).  
   - Если документ в БК уже проведён: перезаписывать / не трогать.  
   - Автоотправка: включена / выключена, интервал.

   **6.5. Условия и ограничения**  
   - COM-соединение работает, только если бухгалтерская база доступна с компьютера или сервера, где запущена управленческая база (файловая база или сервер 1С — локально либо на арендованном сервере). **С базой в 1С:Фреш COM-обмен невозможен.**  
   - На машине, где выполняется обмен, нужна платформа 1С, а сам сеанс обмена занимает лицензию 1С.  
   - Если управленческая база файловая, регламентное задание выполняется только когда открыт хотя бы один сеанс 1С. Для полной автоматики нужен клиент-серверный вариант или запуск по планировщику Windows.  
   - В бухгалтерскую базу ставится небольшое расширение-приёмник: оно создаёт и заполняет документ типовыми механизмами (счета учёта, НДС). Изменения конфигурации БК не требуются.

**Итого по п. 1–6: 34 ч.**

### 3. Что не делаем (вне объёма)

- Полный функционал УНФ (резервы, обеспечение, сборка, CRM, доставка, бонусы, РМК и т.п.).  
- Перенос всех отчётов и интерфейсов УНФ в Бухгалтерию.  
- Доработка типовых отчётов БК (ОСВ, НДС, анализ счетов и пр.) под менеджера.  
- Интеграции с WhatsApp / Telegram / Mobius / SFA.  
- Акции со сложными правилами (если понадобятся — отдельная оценка).  
- Миграция истории заказов из УНФ (по согласованию — отдельно).

---

### 4. Как это выглядит для пользователя

1. Менеджер создаёт заказ на нужное количество.  
2. По мере отгрузки оформляет реализации на часть заказа.  
3. В заказе и в списке видно, сколько уже отгружено (% и остаток).  
4. Следующая реализация предлагает остаток к отгрузке.  
5. Когда отгружено 100% — заказ можно считать выполненным по отгрузке.

Макет списка со шкалой: https://sania2007mav.github.io/kulan-kipchak-zakazy/

---

### 5. Технический контур (кратко)

- Расширение конфигурации (совместимо с 1С:Фреш).  
- Регистр накопления для остатков по заказу (приход — заказ, расход — реализация).  
- Доработка типовой реализации в части связи с заказом и списания остатка (через расширение).  
- Условное оформление динамического списка заказов для шкалы %.  
- Обмен: COM-соединение (V83.COMConnector) из управленческой базы, регламентное задание, регистр сведений для связи документов и журнала обмена, расширение-приёмник в бухгалтерской базе.

---

### 6. Приёмка

Считается выполненным, если:

- [ ] Создаётся и проводится заказ покупателя.  
- [ ] По одному заказу проводится ≥2 реализации на части количества.  
- [ ] В заказе корректно считается «не отгружено».  
- [ ] Третья реализация подставляет остаток; сверх остатка провести нельзя.  
- [ ] В списке заказов отображается % отгрузки с цветовой шкалой.  
- [ ] Заполняется ответственный; есть отбор / простая аналитика по нему.  
- [ ] Работает ввод счёта и реализации на основании заказа.  
- [ ] Расширение устанавливается в базу клиента (Фреш) без ошибок.  
- [ ] Реализация с отметкой уходит в бухгалтерскую базу из формы документа, из списка и регламентным заданием; без отметки — не уходит.  
- [ ] Повторная отправка обновляет тот же документ в БК, дублей нет.  
- [ ] Контрагент находится по БИН/ИИН; при «не найден» работает выбранная настройка (создать или оставить пустым).  
- [ ] Номенклатура находится по артикулу, договор — у найденного контрагента.  
- [ ] Статус обмена и ошибки видны в документе, в списке и в журнале обмена.

---

### 7. Примечание

Это **упрощённый рабочий контур** под задачу клиента, а не замена УНФ.  
Цель — закрыть сценарий «одна заявка — несколько накладных» в одной бухгалтерской базе дёшево и прозрачно.
