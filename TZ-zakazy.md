# Техническое задание  
## Заказы покупателя и частичные отгрузки в 1С:Бухгалтерии КЗ  
**Клиент:** ТОО «Құлан Қыпшақ»  
**Платформа:** 1С:Бухгалтерия для Казахстана 3.0 (1С:Фреш), доработка расширением  
**Дата:** 27.10.2026  

---

### 1. Цель

Дать возможность работать с заказами покупателя прямо в бухгалтерской базе:  
один заказ → несколько реализаций ТМЗ и услуг, с понятным остатком «сколько ещё отгрузить» — без внедрения полного УНФ и без обмена Бух ↔ УНФ.

---

### 2. Что делаем (входит в объём)

1. **Документ «Заказ покупателя»**  
   Шапка: организация, контрагент, договор, склад, валюта, комментарий, ответственный (менеджер).  
   Табличная часть: номенклатура, количество, цена, % скидки, сумма.  
   Проведение документа. Печатная форма. Размещение в разделе «Продажа».

2. **Связка «заказ → реализации»**  
   Из заказа — ввод на основании: реализация ТМЗ и услуг, счёт на оплату.  
   По одному заказу допускается **несколько** реализаций.  
   В реализации фиксируется связь с заказом.  
   Контроль: нельзя отгрузить больше, чем осталось по заказу (по количеству номенклатуры).

3. **Остаток к отгрузке**  
   Учёт: заказано / отгружено / осталось.  
   В форме заказа видно количество «не отгружено» по строкам.  
   При создании следующей реализации подставляется **остаток**, а не полный заказ.

4. **Шкала отгрузки в списке заказов**  
   Колонка «Отгружено, %» (0–100).  
   Цветовое оформление ячейки / полоска: мало / частично / полностью (как на согласованном макете).  
   По желанию — простой статус (в работе / частично / отгружен).

5. **Ответственный (менеджер)**  
   Поле на заказе (справочник пользователей).  
   При вводе реализации — перенос с заказа.  
   Отбор в списке заказов.  
   Один простой отчёт / выборка «по менеджеру» (без переделки типовых бухгалтерских отчётов).

6. **Скидка в строке заказа**  
   Процент скидки в ТЧ, пересчёт суммы строки.

---

### 3. Что не делаем (вне объёма)

- Полный функционал УНФ (резервы, обеспечение, сборка, CRM, доставка, бонусы, РМК и т.п.).  
- Перенос всех отчётов и интерфейсов УНФ в Бухгалтерию.  
- Доработка типовых отчётов БК (ОСВ, НДС, анализ счетов и пр.) под менеджера.  
- Интеграции с WhatsApp / Telegram / Mobius / SFA.  
- Акции со сложными правилами (если понадобятся — отдельная оценка).  
- Миграция истории заказов из УНФ (по согласованию — отдельно).

---

### 4. Как это выглядит для пользователя

1. Менеджер создаёт заказ на нужное количество.  
2. По мере отгрузки оформляет реализации на часть заказа.  
3. В заказе и в списке видно, сколько уже отгружено (% и остаток).  
4. Следующая реализация предлагает остаток к отгрузке.  
5. Когда отгружено 100% — заказ можно считать выполненным по отгрузке.

Макет списка со шкалой: https://sania2007mav.github.io/kulan-kipchak-zakazy/

---

### 5. Технический контур (кратко)

- Расширение конфигурации (совместимо с 1С:Фреш).  
- Регистр накопления для остатков по заказу (приход — заказ, расход — реализация).  
- Доработка типовой реализации в части связи с заказом и списания остатка (через расширение).  
- Условное оформление динамического списка заказов для шкалы %.

---

### 6. Приёмка

Считается выполненным, если:

- [ ] Создаётся и проводится заказ покупателя.  
- [ ] По одному заказу проводится ≥2 реализации на части количества.  
- [ ] В заказе корректно считается «не отгружено».  
- [ ] Третья реализация подставляет остаток; сверх остатка провести нельзя.  
- [ ] В списке заказов отображается % отгрузки с цветовой шкалой.  
- [ ] Заполняется ответственный; есть отбор / простая аналитика по нему.  
- [ ] Работает ввод счёта и реализации на основании заказа.  
- [ ] Расширение устанавливается в базу клиента (Фреш) без ошибок.

---

### 7. Примечание

Это **упрощённый рабочий контур** под задачу клиента, а не замена УНФ.  
Цель — закрыть сценарий «одна заявка — несколько накладных» в одной бухгалтерской базе дёшево и прозрачно.
